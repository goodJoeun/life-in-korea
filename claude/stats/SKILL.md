# 1,000명 시뮬레이션 통계

## 왜 따로 하나

`simulate.ts` 는 모든 선택을 '운에 맡기기'로 해서 실제 통계와 맞춘다.
실제 플레이어는 직접 고르고 돈도 굴린다. 그래서 **사람처럼 고르는 가상 플레이어**로 따로 돌려,
게임이 너무 쉽거나 한쪽 선택만 유리하지 않은지 본다.

## 가상 플레이어 (`scripts/stats.ts`)

| 유형 | 고르는 방식 | 돈 |
|------|-------------|----|
| 운에 맡기기 | autoChoiceIndex | 기본 계획 |
| 무작위 | 선택지 고르게 | 무작위 계획 |
| 안정형 | 안정·성실 쪽 선택지 | 절약 + 예금 80% |
| 도전형 | 도전 쪽 선택지 | 보통 + 주식·코인 |
| 공부형 | 학업·성실 쪽 | 절약 + 주식 지수 |

출생연도는 1960~2026 고르게, 유형별 200명 = 1,000명.

## 보는 것

- 수명, 학력, 30세 직업, 결혼·자녀, 50세 자가, 60세·마지막 순자산 (중앙값·상위 10%·하위 10%)
- 유형별 차이: 선택이 결과를 얼마나 바꾸는지 (너무 크면 게임이 쉬워지고, 0이면 선택이 의미 없다)
- 갈림길이 한 생에 몇 번 나오는지, 어떤 갈림길이 한 번도 안 나오는지
- 한 생의 플레이 시간 (기본 모드 기준 분)

`npx tsx scripts/stats.ts` → `claude/stats/REFERENCE.md` 를 다시 쓴다.
