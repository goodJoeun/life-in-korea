# 개발 로드맵

한 번에 다 만들지 않고, 아래 순서대로 한 단계씩 만들고 → 테스트하고 → 커밋한다.
단계마다 관련 SKILL.md 를 먼저 읽고, 끝나면 이 문서의 상태와 그 SKILL.md 를 고친다.

## 순서와 이유

| # | 단계 | SKILL | 상태 |
|---|------|-------|------|
| 0 | 설계 문서(이 디렉터리) | roadmap | 완료 |
| 1 | 테스트 도구: 무작위 선택 스모크 테스트, 되살리기 검증, 시대 검사 | [testing](../testing/SKILL.md) | 완료 |
| 2 | 현실성: 세대(출생연도) 조건, 어색한 사건 정리 | [realism](../realism/SKILL.md) | 완료 |
| 3 | 플레이 시간: 한 생의 길이 고르기, 한 해 안에서 문장이 차례로 나오기 | [pacing](../pacing/SKILL.md) | 완료 |
| 4 | 성향·관심 분야와 갈림길: 선택이 쌓여 방향이 정해지고, 그에 맞춘 선택지 | [paths](../paths/SKILL.md) | 완료 |
| 5 | 돈 관리: 저축 성향, 예금·주식·펀드·코인 배분, 시대별 수익률 | [money](../money/SKILL.md) | 완료 |
| 6 | 결과 리포트: 생애 그래프, 성향, 또래 비교 | [report](../report/SKILL.md) | 예정 |
| 7 | 1,000명 시뮬레이션 통계 | [stats](../stats/SKILL.md) | 예정 |

- 테스트(1)를 먼저 만든다. 뒤의 단계가 모두 엔진을 건드리므로, 깨지면 바로 알 수 있어야 한다.
- 현실성(2)은 엔진 구조를 바꾸기 전에 사건 데이터의 조건만 손본다. 작은 변경이라 먼저 끝낸다.
- 플레이 시간(3)이 길어져야 갈림길(4)이 많아져도 숨이 차지 않는다. 둘은 같이 봐야 하지만 3을 먼저 커밋한다.
- 돈 관리(5)는 '저축·투자 성향'이 성향 시스템(4)과 이어지므로 4 다음.
- 결과 리포트(6)는 4·5가 남긴 기록(성향, 자산 흐름)을 보여 주므로 마지막에서 두 번째.
- 통계(7)는 모든 기능이 들어간 뒤 사람처럼 고르는 가상 플레이어 1,000명으로 낸다.

## 지켜야 할 것 (CLAUDE.md 요약)

- `src/lib/*` 는 React·DOM 금지. Node 시뮬레이터가 그대로 돌린다.
- 엔진·데이터를 고치면 `npx tsx scripts/simulate.ts all` 로 진학률·초혼·자녀 수·자산이 크게 벗어나지 않았는지 본다.
- 정적 export 유지. 서버 기능 금지.
- 문장은 과거형 일기체. 조사는 `josa()`/`particle()`.
- 사망 원인에 자살을 넣지 않는다.
- 커밋은 관심사별로 나눈다. 한 단계 = 1~3개 커밋.

## 매 단계 끝에 할 일

1. `npm run typecheck` · `npm test` · (엔진을 건드렸으면) `npx tsx scripts/simulate.ts all`
2. 브라우저에서 해당 화면 확인 (헤드리스 Edge 스크린샷 가능: testing SKILL 참고)
3. 이 표의 상태와 해당 SKILL.md 갱신
4. 관심사별 커밋
